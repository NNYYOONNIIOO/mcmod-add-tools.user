# MC百科添加工具

当前版本：**1.4.8**。脚本用于 MC 百科，支持从 CurseForge 导入模组信息，以及使用物品导出文件批量填写资料。

脚本在以下页面显示对应面板：

| 页面 | 功能 |
| --- | --- |
| `https://www.mcmod.cn/class/add/` | 从 CurseForge 抓取模组信息，预览封面及翻译正文 |
| `https://www.mcmod.cn/class/数字.html` | 选择导出工具、导入物品文件和继续已有队列 |
| `https://www.mcmod.cn/item/add/数字/` | 按队列填写、提交、跳过或停止添加物品 |

同一功能也支持不带 `www` 的 MC 百科域名。脚本不会在 CurseForge 网站显示面板。

## 安装和更新

1. 若已安装本脚本或旧版“MC百科 CurseForge 投稿助手”，在 ScriptCat 中打开原脚本的编辑器，用同目录 `mcmod-add-tools.user.js` 的全部内容替换原代码并保存，以保留已有设置并避免创建重复脚本。
   首次安装时，直接导入 `mcmod-add-tools.user.js` 并确认启用。
2. 确认脚本已在 ScriptCat 中启用，然后打开或刷新相应的 MC 百科页面。
3. 在模组添加页确认面板标题为“MC百科添加工具”，底部显示“版本 1.4.8”。

## 从 CurseForge 导入模组

1. 登录 MC 百科并打开 `https://www.mcmod.cn/class/add/`。
2. 在右上角面板粘贴 CurseForge 的 Minecraft 模组链接，例如 `https://www.curseforge.com/minecraft/mc-mods/jei`。
3. 勾选需要填写的项目，点击“抓取并填表”。完成后查看面板的信息，检查自动填写的内容，再由自己提交。

CurseForge 地址不会保存，每次重新打开投稿页时输入框都会为空。面板只会保存填表选项、“覆盖已有内容”状态、窗口位置和 AI 翻译设置。

当 CFWidget 按项目路径查询失败时，脚本会尝试从 CurseForge 项目页读取 Project ID 并改用 ID 查询；如果项目页也无法读取，可以使用 `https://www.curseforge.com/minecraft/mc-mods/项目ID` 形式的地址重试。ID 查询成功后会使用返回的项目正式地址。

脚本会尝试填写英文名称、CurseForge Project ID、相关链接、作者/开发团队、加载器与 MC 版本、运行环境、模组关系、官方状态和许可协议。若 CurseForge 提供 Modrinth 项目链接，脚本优先直接读取该项目并填写 Modrinth Project ID；没有链接时再按名称搜索。自动填写的内容都是待核对草稿。

勾选“覆盖已有名称、状态、封面、链接、作者、关系和许可”时，脚本会替换勾选栏目中的已有链接、作者、模组关系和许可条件组；未勾选的栏目不清除。若没有取得某一类的可用替代数据，则保留该类原内容。搜索到的作者或模组如果无法关联，仍需按面板提示手动处理。

CurseForge 页面受限粘贴区和 CurseForge API Key 设置已移除；导入流程不需要 CurseForge API Key。AI 正文翻译所需的 API Key 与 CurseForge 无关，仍可在“AI 正文翻译”中单独设置。

## 模组关系和画廊

- CurseForge 的 Required Dependency 会按“前置”候选导入，Optional Dependency 会按“联动”候选导入，并在百科按名称搜索。找到唯一的精确名称或别名时自动加入关系；找不到、匹配不唯一、搜索失败或无法添加时，面板会说明需要手动处理。联动关系仍需按模组代码和实际功能核对。
- 项目只支持一个 Minecraft 版本时，前置关系使用“通用”组，不填写加载器或版本。项目支持多个版本时，关系组条件使用 `Forge 1.20.1`、`Fabric 1.14` 或 `1.12.2` 等简洁写法。版本资料不足时面板会提示；依赖关系来自项目级资料和最新文件，适用范围仍需核对。
- 关系组控件位于百科关系容器外侧时也会尝试识别；百科的新增控件没有响应时，脚本会按百科表单结构补建关系组。若页面没有可用的关系位置，面板会提示手动处理。
- 默认启用“导入 CF 图库”。脚本读取 CurseForge 项目图库及项目介绍正文中的附件图片，将图片导入 MC 百科图片服务，再在正文末尾添加 `[h1=画廊]` 和横向排列的单图单格表格。图片高度设为 300 像素；受可用宽度限制时按比例缩放。头像等非附件图片不会导入。
- 若 CurseForge 图片不可读，或百科图片服务无法导入某张图片，该图片会跳过并在面板提示；未导入的外链不会写进正文。

## 运行环境和封面

- 脚本优先使用 CurseForge 的 Environment，并在可用时结合 Modrinth 的客户端、服务端兼容信息。CurseForge 的 `Client & Server` 只能表明支持两端；没有更详细的信息时，脚本会给出“双端需装”候选并提示核对。
- 勾选“生成封面”后，脚本优先使用 CurseForge 原始高清图片，在浏览器内生成 768 × 480 的 PNG。面板提供透明边缘、两侧模糊和延伸边缘三种预览；智能判断的结果默认选中，点击其他预览即可切换。
- “下载当前封面”保存当前选中的生成结果；原始高清图片读取成功时，“下载原图”可保存未经处理的图片。若高清原图不可用、脚本退回使用缩略图，原图按钮不可用。已有封面时，只有勾选覆盖选项才会替换。

## AI 正文翻译

1. 展开“AI 正文翻译”，填写服务商的 Chat Completions HTTPS 完整地址、模型名称和个人 API Key，再点击“保存设置”。地址需要包含 `/chat/completions`；智谱默认地址为 `https://open.bigmodel.cn/api/paas/v4/chat/completions`，默认模型名为 `glm-4.7-flash`；账户支持的模型 ID 以服务商为准，可自行修改。
2. 抓取项目后，描述会转换成 Markdown，供检查和编辑；没有读取到描述时可以手动粘贴 Markdown。点击“翻译并预览”后，正文才会发送至所填 AI 服务。该服务可能产生费用，并适用服务商的数据处理规则。
3. 检查中文 Markdown 预览后，点击“写入百科正文”。脚本调用百科的“应用快速排版”处理译文，再追加到已有正文和画廊之前；脚本不会自动提交。百科快速排版尚未加载或无响应时，不会写入正文，译文仍保留在预览中。

翻译规则已内置在脚本中，**不需要另行安装 Skill**。规则要求模型保留 Markdown 结构、专有名称、版本、命令、链接和原意，不补写事实。较长正文会分段请求，每次最多处理 60000 字符。API Key 保存在 ScriptCat 扩展存储中，可点击“清除 Key”移除。只应填写信任的服务地址。

## 核对事项

- 官方状态按 CurseForge 最新文件时间估算：6 个月内为活跃，6 至 12 个月为半弃坑，超过 12 个月为停更；请结合作者公告复核。
- 项目页没有源码链接时，脚本可能根据项目名称和 README 内容匹配 GitHub 仓库，并将其标记为候选；请确认仓库确实属于该项目后再采用许可信息。
- CurseForge 与 GitHub/GitLab 仓库声明可确认相同的协议时，合并为一条“默认”类型许可，链接指向源码仓库；两边声明不同或仅有一边可读时，分别按“构件”和“源码”填写。CurseForge 显示自定义协议时，面板会提示打开原页面核对具体条款。
- 源码许可仅能从部分 GitHub/GitLab 仓库识别；只有已识别的源码开放许可会作为开源状态候选。源码、资源和构件可能采用不同许可，开源状态及适用条件需要复核。页面受限或许可声明不可读时，脚本会提示并保留已有信息。
- 作者搜索无结果时，脚本会在当前表单加入待创建作者，不会单独提交创建作者。

## 批量添加物品

1. 登录 MC 百科并打开模组详情页，例如 `https://www.mcmod.cn/class/数字.html`。右上角会显示“批量添加物品”面板。
2. 从下拉框选择游戏版本；版本不在列表时选择“其他版本”并输入。导出工具会按已确认的兼容版本筛选：只有一个工具支持时自动选择，两个都支持时可自行选择；版本未列入已确认的兼容范围时，两种格式均可尝试。请选择实际使用的工具，两者的最大耐久数值含义存在差异。支持逐行 JSON/JSONL、JSON 数组或单个 JSON 对象。
3. 将物品导出文件拖到面板，确认条目数量后点击“开始批量填写”。脚本会按文件顺序打开 `https://www.mcmod.cn/item/add/数字/`，尝试填写名称、大小图标、物品/方块资料类型以及可识别的数值和标签。创造模式物品栏名称与百科分类完全一致时尝试选择该分类。
4. 检查每条资料后，可点击面板中的“添加资料”快捷按钮；它只会触发百科原有的“添加资料”按钮，因此百科的验证、警告和确认流程仍会照常出现。也可以直接点百科原按钮。只有百科正式提交接口返回成功后，脚本才会进入下一条；验证未通过、取消确认或提交失败都不会跳过当前条目。若当前物品不需要添加，可点击“跳过当前项”；提交请求进行时需等待结果后才能跳过。
5. 意外关闭页面后，回到模组详情页可点击“继续批量填写”恢复已有队列。在物品页面点击“停止批量添加”或“返回模组页”会清除队列。全部提交或跳过后会返回模组详情页。

导出工具的选项按脚本内的已确认版本筛选，例如 `1.12.2` 显示 Item Render Rebirth，`1.20.1` 显示 IconRenderer，`1.16.5` 可选择两者。这个筛选只考虑游戏版本，请自行确认工具和所用加载器是否匹配。导入文件后切换工具时，脚本会按新选择重新解析文件。

导出文件会保存在当前 MC 百科域名的浏览器 IndexedDB 中作为当前队列，ScriptCat 扩展存储只保留队列进度和选项；脚本不会上传导出文件到第三方服务。在同一浏览器配置和同一百科域名下恢复队列；重新开始新队列会替换原队列。图标使用导出 JSON 中的 Base64 数据；Item Render Rebirth 和 IconRenderer 的常见字段拼写差异会自动兼容。实体导出文件不适用于此功能。

游戏版本用于记录并尝试匹配百科页面中的 Minecraft 版本控件；百科的“首次出现”指模组版本，不能直接用游戏版本代填。无法填写或未能完整填写的值会显示在信息栏，点击值即可选中复制。实际页面上的分类、注册名等字段是否能自动填写还需登录后核对。脚本不会自动查重，每条提交仍需检查。

最大耐久为 0 时会留空。所提供的 Item Render Rebirth 源码会将最大损耗值加 1 后导出，因此选择该工具时，导出的最大耐久为 1 表示原始最大损耗值为 0，也会留空；IconRenderer 的值 1 则仍按 1 处理。如果百科输入控件不接受元数据 0，脚本不会把它改写成 1，而会保留原值并在信息栏给出 0。

批量窗口的折叠状态会在模组页和物品添加页之间保留；折叠时窗口宽度不变。
